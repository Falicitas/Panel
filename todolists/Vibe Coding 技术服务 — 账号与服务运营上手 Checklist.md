# Vibe Coding 技术服务 — 账号与服务运营上手 Checklist

从零开始，把小红书和闲鱼两个新号跑通，形成稳定的获客-转化-交付流程。
前置条件：服务帖已发，定价已定（250/500/200），远程 pair programming 模式。

---

## Phase 0 — 账号基建 (~30min)

把两个平台的账号从"刚注册"变成"看起来像个正经服务商"。

- [ ] 小红书：设置头像 — 用你本人照片或一张终端/代码截图风格的图。不要用默认头像，新号+默认头像=零信任
- [ ] 小红书：写简介 — 一行写你是谁（算法金牌 / 全栈），一行写你做什么（帮 vibe coder 上线），一行写怎么联系（私信）。不要写一大段
- [ ] 小红书：置顶服务帖 — 把已发的那条"Vibe 出来了该上线赚钱了"设为置顶
- [ ] 闲鱼：设置头像和昵称 — 同上，保持跟小红书一致
- [ ] 闲鱼：确认服务帖的标题包含搜索关键词 — "vibe coding"、"cursor"、"copilot"、"部署"、"上线"、"编程"、"远程开发"至少覆盖 4 个
- [ ] 闲鱼：从不同角度再发 2-3 个宝贝 — 一个侧重"部署上线"，一个侧重"性能优化"，一个侧重"支付/API 对接"。每个标题对应一个具体场景
  - 🔍 闲鱼的流量主要来自搜索匹配，多个宝贝 = 多个入口

---

## Phase 1 — 内容冷启动：发出前 10 条小红书 (~3h，分 3-5 天)

新号有流量扶持期，前 10 条的互动数据决定后续推荐量。目标：每条至少过 200 曝光。

- [ ] 准备 10 个选题 — 从下面的选题池里挑，或者根据你实际帮人解决过的问题来写：
  - "Cursor 生成的代码为什么一改就崩"
  - "vibe 出来的项目怎么部署到服务器（最简路径）"
  - "用 AI 写代码，什么时候该停下来找人帮忙"
  - "vibe coding 项目上线前要检查的 5 件事"
  - "帮一个 vibe coder 把项目部署上线，花了 X 分钟"（实战复盘）
  - "Cursor 能帮你写代码，但这几件事它搞不定"
  - "独立开发者的项目从 demo 到上线差在哪"
  - "为什么你的 vibe 项目本地能跑线上就挂"
  - "接支付最简单的方案（给 vibe coder 的）"
  - "代码越改越乱怎么办：什么时候该重构"
- [ ] 写第 1 条并发布 — 选一个你最有话说的选题，控制在 300-500 字。配图用终端截图或代码截图，不要纯文字
  - 🔍 小红书的内容格式：封面图决定点击率，正文前两行决定是否继续读。封面图上放大字标题，正文开头直接说事，不要"大家好我是xxx"
- [ ] 发完第 1 条后观察 24h 数据 — 看曝光、点击、收藏、评论。记下来，后面对比用
- [ ] 连续 5 天每天发 1 条 — 时间选晚上 8-10 点或中午 12-1 点，这两个时段活跃用户多
- [ ] 第 6-10 条可以隔天发 — 保持节奏但不用太赶
- [ ] 每条发完后，去搜索"vibe coding"、"cursor 部署"等关键词，找到相关帖子，留 2-3 条有价值的评论 — 不是打广告，是回答别人的问题，让人点进你主页
  - 🔍 评论引流是新号获取精准流量最快的方式。评论内容要有信息量，比如"这个问题一般是 nginx 配置没改 server_name，你检查一下"

## Phase 2 — 客户转化流程 (~1h)

有人私信了，怎么从"聊天"变成"付款开干"。提前把流程想好，不要每次临场发挥。

- [ ] 写一个标准的首次回复模板 — 对方私信后，你需要收集：项目是什么、用什么技术栈、卡在哪个具体问题、想达到什么效果。写成 4-5 个问题，私信直接发
- [ ] 确定收款方式 — 闲鱼走平台交易（拍宝贝付款）。小红书私信引导到哪里收款？微信？支付宝？提前想好
  - 🔍 闲鱼的优势是有平台担保，买家更敢付钱。小红书需要额外建立信任
- [ ] 写一个"评估后不合适"的回复模板 — 有些问题你帮不上（比如要求写整个项目、或者技术栈你不熟），提前准备好怎么拒绝。拒绝得体本身也在建口碑
- [ ] 确定会议工具 — 腾讯会议 / 飞书 / Google Meet，提前测试屏幕共享是否流畅
- [ ] 做第一单（哪怕免费或半价） — 目标是跑通整个流程：私信 → 评估 → 约时间 → session → 收款。第一单的体验会暴露流程里的问题
  - 💡 如果短期内没有自然流量来的客户，可以在独立开发者群里发个"前 3 单半价"

---

## Phase 3 — 交付质量 (~30min)

session 结束不是服务结束。做好售后，让客户愿意给好评和转介绍。

- [ ] session 结束后发一个文字总结给客户 — 写清楚：做了什么、改了哪些文件、为什么这么改、后续建议。5-10 行就够
  - 🔍 这个总结有两个作用：客户能回顾，你自己也积累了案例素材
- [ ] 请客户给评价 — 闲鱼：引导确认收货并评价。小红书：问客户能不能截个图或写条反馈
- [ ] 把 session 内容脱敏后整理成小红书素材 — "帮一个 vibe coder 解决了 XX 问题"这类实战帖是最有说服力的内容
- [ ] 建一个简单的记录表 — 日期、客户问题、技术栈、用时、结果、收入。Excel 或 Notion 都行，周末看一眼趋势

---

## Phase 4 — 闲鱼运营节奏 (~15min/天)

闲鱼跟小红书的运营逻辑不同，单独拎出来。

- [ ] 每天"擦亮"一次宝贝 — 编辑宝贝后重新保存，相当于刷新排名
- [ ] 每周调整一次标题关键词 — 去闲鱼搜"编程辅导"、"代码帮助"、"cursor"等词，看排在前面的帖子用了什么关键词，跟着调
- [ ] 回复咨询要快 — 闲鱼有"回复速度"指标，影响排名。手机装好闲鱼 app，开通知
- [ ] 如果某个宝贝持续没曝光 — 删掉重发，换标题换封面

---

## 品味校准 (~5min)

- [ ] 判断：这个服务在小红书/闲鱼上能长期做还是短期红利？为什么？
- [ ] 你的目标客户画像是什么？他们平时在这两个平台上搜什么词、看什么内容？
- [ ] 跟你竞争的是谁？搜一下"编程辅导"、"代码帮助"、"程序员接单"，看看别人怎么定价、怎么写文案
- [ ] 目前的定价（250/500/200）在你看到的竞品里处于什么位置？高了还是低了？
- [ ] 一句话总结：如果一个月后这个服务没跑起来，最可能的原因是什么？
