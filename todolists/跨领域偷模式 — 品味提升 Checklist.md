# 跨领域偷模式 — 品味提升 Checklist

从零开始建立"跨界模式迁移"的习惯。每周投入 1~2 小时，刻意从非技术领域提取设计原则，映射到你做的产品和技术决策上。
前提：你已经有大量技术领域的输入（每天 4-5 个开源项目），缺的是跨界的审美锚点。

---

## Phase 0 — 选定三个"偷取"领域 (~15min)

从你已有的兴趣出发，选三个跟日常工作完全不同的领域作为长期输入源。

- [ ] 列出你已有但没刻意利用的跨界兴趣 — 你在读 Mankiw 经济学、对航天/机器人感兴趣、有金融市场背景，这些都算
- [ ] 从以下候选里挑三个，要求彼此不重叠：
  - 工业设计 / 产品设计（实体物品的 form + function 权衡）
  - 游戏设计 / 游戏机制（反馈循环、progression system、玩家心理）
  - 建筑设计（空间、流线、材料约束下的优雅）
  - 平面设计 / 字体设计（视觉层级、信息密度、排版节奏）
  - 音乐制作 / 编曲（结构、层次、tension-release）
  - 写作 / 叙事设计（节奏、信息披露顺序、读者预期管理）
  - 经济学 / 机制设计（激励结构、均衡、博弈）
  - 航天工程 / 机械设计（极端约束下的可靠性、冗余设计）
- [ ] 把选好的三个领域写下来，固定下来至少跑三个月不换
  - 🔍 理解点：品味建立需要在一个领域积累足够深度才能提取模式，频繁换领域只会停留在表面

---

## Phase 1 — 每个领域找到一个"锚点内容源" (~30min)

每个领域找到一个高质量、可持续消费的内容源，不需要很多，一个就够。

- [ ] 工业设计类 — 从以下挑一个订阅/收藏：
  - YouTube: Dieter Rams 纪录片 "Rams"（一次性看完建立基准线）
  - 书：原研哉《设计中的设计》或 Don Norman《设计心理学》
  - YouTube 频道: Technology Connections（把日常物品的设计决策拆到极致）
- [ ] 游戏设计类 — 从以下挑一个：
  - GDC Vault 免费演讲（搜 "game design" 按热度排序，每周看一个）
  - 书：Jesse Schell《The Art of Game Design》（跳着读 lens 部分就行）
  - YouTube 频道: GMTK（Game Maker's Toolkit，每期 10-15min，拆解游戏机制）
- [ ] 第三领域 — 根据你选的领域自己找，标准：内容创作者本身是从业者而非科普博主，内容涉及 tradeoff 和决策过程而非只展示结果
- [ ] 把三个内容源存到一个固定地方（备忘录、Notion、浏览器书签文件夹都行）
  - 🔍 理解点：瓶颈不是找不到好内容，是没有固定入口导致每次都要重新决定"今天看什么"

---

## Phase 2 — 建立"模式提取"的动作习惯 (~20min)

光看不够，关键是看完后做一个固定动作：提取模式并映射。

- [ ] 准备一个"跨界模式笔记"的地方 — 可以是一个 markdown 文件、一个 Notion 数据库、或者纸质笔记本，格式固定为：
  ```
  日期：
  领域：
  看了什么：
  这个领域认为什么是"好"的：（一句话）
  提取的模式/原则：（一句话）
  映射到我的工作：（一句话）
  ```
- [ ] 试跑一次 — 随便从 Phase 1 的内容源里看一段内容（15min 左右），然后填上面的模板
  - 示例：看了 Dieter Rams 的 "Good design is as little design as possible" → 提取模式："约束越多的环境，减法比加法更考验品味" → 映射："桃源天下的 K 线图工具栏是不是功能太多了？哪些可以砍掉？"
- [ ] 检查自己的映射是否具体 — 如果映射结果是"要注重用户体验"这种泛泛的话，说明提取得不够锐利，重新写一遍，逼自己指向一个具体的产品决策

---

## Phase 3 — 嵌入周节奏 (~10min)

把跨领域输入变成每周固定 slot，不靠意志力靠流程。

- [ ] 在日历上 block 一个固定时段 — 每周 1~2 小时，建议放在周末或工作日晚上精力不够写代码但还能看东西的时候
- [ ] 定义每次的最小完成标准 — 看一段内容（视频/文章/书的一章）+ 填一条模式笔记，做到这两件事就算完成
- [ ] 设定三个月后的 review 节点 — 在日历上标一个提醒，届时回看所有模式笔记，找出哪些映射真的影响了你的决策，哪些是空话

---

## Phase 4 — 进阶：主动寻找"同构" (~15min)

从被动接收升级到主动对比。

- [ ] 💡 拿你最近做的一个技术决策，去跨界领域里找对应物 — 比如你在 LLM gateway 里做的 rate limiting 设计，去看交通工程里的"信号灯配时"是怎么做 congestion control 的，或者经济学里的"价格机制"怎么做资源分配
- [ ] 💡 反过来：拿跨界领域里一个你觉得优雅的设计，问自己"如果把这个原则用在我现在的项目里，会怎么做" — 不需要真的做，写下来就行
- [ ] 💡 找到一个"同构"之后，写一条推文或笔记把这个类比说清楚 — 这个输出动作会逼你把模糊的直觉变成清晰的表达

---

## 品味校准 (~5min)

- [ ] 判断：这个"跨领域偷模式"的方法本身，你觉得三个月后你还会坚持吗？为什么？
- [ ] 你选的三个领域够"远"吗？如果三个领域跟你日常工作的认知距离太近（比如全是 tech 相关），模式迁移的价值会打折
- [ ] 核心 tradeoff：每周 1-2 小时花在跨界上，意味着少看 5-10 个开源项目。这个时间投资你认同吗？
- [ ] 一句话总结：跨领域输入对你当前阶段（创业 + 求职）的 ROI 判断
