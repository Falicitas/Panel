# Vibe Coding 技术服务 — 进阶运营 Checklist

前置：上手 Checklist 已完成，跑通了从发帖到交付的完整流程，至少做了 3-5 单。 目标：从"偶尔有单"到"稳定获客"，建立可复制的运营节奏。

------

## Phase 0 — 数据复盘 (~1h)

拿着前面积累的数据做一次诊断，找到瓶颈在哪。

-   [ ] 统计小红书每条帖子的曝光、点击、收藏、评论 — 找出数据最好的 3 条和最差的 3 条，对比它们的选题、封面图、发布时间
    -   🔍 小红书的数据在"创作者中心"里可以看到。重点看"点击率"（点击/曝光），低于 5% 说明封面图或标题有问题
-   [ ] 统计转化漏斗 — 曝光 → 主页访问 → 私信 → 成单，每一步的转化率是多少？卡在哪一步？
    -   曝光到点击低：封面图/标题问题
    -   点击到私信低：正文没有说清楚服务内容，或者缺少行动号召
    -   私信到成单低：定价问题，或者评估沟通环节有摩擦
-   [ ] 统计闲鱼每个宝贝的曝光和咨询量 — 哪个角度切入的宝贝效果最好？
-   [ ] 统计客单和时长 — 平均每单实际花多少时间？250 的单和 500 的单比例怎样？时薪算下来是多少？

------

## Phase 1 — 内容迭代 (~2h)

根据数据调整内容策略，放大有效的，砍掉没用的。

-   [ ] 确定 2-3 个"能跑"的内容类型 — 从已发的帖子里找到数据最好的类型，后面围绕这几个类型批量生产
    -   常见的能跑类型：实战复盘帖（帮客户解决了什么）、具体技术教程帖、"X 件事 vibe coder 容易忽略"类的 list 帖
-   [ ] 做封面图模板 — 固定一个风格（字体、配色、排版），以后每条帖子换文字就行，省时间
    -   🤖 可以让 Claude 批量生成不同标题的封面图 SVG，统一风格
-   [ ] 建一个选题库 — 把你在 session 中遇到的客户问题都记下来，每个问题都是一条帖子的选题。真实案例比编的内容有说服力
-   [ ] 试一次"系列帖" — 比如"Vibe Coding 上线指南"系列：第 1 篇讲部署，第 2 篇讲数据库，第 3 篇讲支付。系列帖能互相导流，也让主页看起来有体系
-   [ ] 发帖频率调整 — 数据好的时期保持每天 1 条，数据平稳后隔天 1 条就够。质量比数量重要

------

## Phase 2 — 扩展获客渠道 (~2h)

小红书和闲鱼之外，还有几个渠道适合这类服务。

-   [ ] 即刻 — 注册账号，关注"独立开发者"、"AI 工具"、"vibe coding"相关话题。先评论互动一周，再发服务帖。即刻的社区氛围比小红书松，直接说"我提供这个服务"不会被踩
-   [ ] V2EX — 在"酷工作"或"推广"节点发一条。V2EX 用户技术水平高，描述问题要更具体
-   [ ] 独立开发者微信群 — 如果你在任何 indie hacker / 独立开发相关的群里，发那条极短版文案。如果不在，先加几个群（即刻上经常有人拉群）
-   [ ] 💡 GitHub — 如果你有开源项目或者写过技术文章，在 README 或 bio 里加一行你的服务链接
-   [ ] 💡 知乎 — 回答"如何部署 xxx"、"cursor 生成的代码怎么优化"这类问题，在回答末尾提一句你的服务。知乎的长尾搜索流量不错
-   [ ] 评估每个渠道的 ROI — 花了多少时间，带来多少咨询，转化多少单。一个月后砍掉没效果的渠道

------

## Phase 3 — 服务产品化 (~1h)

把零散的 session 整理成标准化的服务套餐，降低沟通成本。

-   [ ] 梳理客户问题分类 — 到现在你接的单主要集中在哪几类问题？部署？性能？架构？支付？按频率排序
-   [ ] 为 top 3 问题类型写标准化的服务描述 — 比如"部署上线包"：包含什么（域名配置、SSL、CI/CD、基础监控），预期时长，定价。让客户看完就知道自己要不要买
-   [ ] 💡 考虑是否需要调价 — 如果你发现大部分单都在 1h 内解决，250 可能偏低。如果客户的项目复杂度普遍超出预期，考虑加一个"4h 深度 session"的选项
-   [ ] 💡 考虑"诊断报告"作为低价引流产品 — 客户发你代码仓库链接，你花 15 分钟看一遍，给一份文字诊断（问题在哪、怎么改、预估工时）。收 50-100 块。这个产品的作用是降低客户的决策门槛，看完诊断再决定要不要买 session
-   [ ] 做一个服务案例集 — 把做过的 session 脱敏整理成 3-5 个案例，每个案例写：客户背景、问题、解决方案、结果。放在小红书置顶帖或者落地页上

------

## Phase 4 — 口碑和复购 (~30min)

获客成本最低的渠道是老客户转介绍。

-   [ ] 每单结束后 3 天，私信客户问一句"项目跑得怎么样" — 这不是套话，如果他遇到新问题，你又有一单
-   [ ] 设计一个转介绍机制 — 简单点：老客户介绍新客户，新客户首单减 50。不用做得很复杂
-   [ ] 收集客户的文字反馈或截图 — 作为信任素材放在帖子和落地页上。有真人说"这个服务帮我把项目上了线"比你自己说一百遍都管用
-   [ ] 💡 建一个客户微信群 — 如果做到 10+ 个客户，拉个群。群里你偶尔分享技术内容，客户之间也能互相帮忙。群本身就是你的私域

------

## Phase 5 — 运营节奏固化 (~15min)

把运营变成习惯，不要靠意志力。

-   [ ] 定一个每周运营时间表，写下来贴在桌上：
    -   每天 10min：回复私信和闲鱼咨询，擦亮闲鱼宝贝
    -   每 2 天 30min：写 1 条小红书帖子
    -   每周日 30min：看一遍本周数据，调整下周选题
-   [ ] 设一个"内容素材"随手记 — 手机备忘录或者微信的"文件传输助手"。session 中遇到的问题、客户说的话、你的解决思路，随手记一句，周末整理成帖子
-   [ ] 每月做一次完整复盘 — 收入、客户数、渠道分布、时薪、内容数据。跟上个月对比

------

## 品味校准 (~5min)

-   [ ] 判断：这个服务做到什么规模就到天花板了？瓶颈是时间（你只有一个人）、流量（获客跟不上）、还是客单价（250/h 的天花板）？
-   [ ] 如果要突破天花板，可能的路径是什么？比如：录制付费课程、做标准化工具/模板卖、带团队接单、转向更高客单价的咨询。哪个跟你现在的方向最近？
-   [ ] 你的竞争优势在哪？是技术能力、是响应速度、是沟通方式、还是别的？这个优势能持续多久？
-   [ ] 你在运营上花的时间和在 session 上花的时间比例怎样？理想比例是多少？
-   [ ] 一句话总结：三个月后回头看，这个服务对你来说是赚钱工具、获客渠道、还是个人品牌建设？
